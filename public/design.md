# PeopleHub --- Landing Page Design Specification

## 1. Design Goal

Create a premium, modern HR Management SaaS landing page based directly
on the supplied visual reference.

The page should communicate:

-   Modern HR technology
-   Enterprise-grade reliability
-   Simplicity
-   Productivity
-   Trust
-   People-first software
-   Premium SaaS positioning

The visual direction is **light, clean, spacious, and polished**, with
soft blue atmospheric gradients and highly refined SaaS dashboard UI.

The supplied reference image is the primary visual source. The
implementation should preserve its composition, hierarchy, proportions,
spacing, and visual language rather than introducing a different design
direction.

# 3. Visual Direction

### Overall Style

-   Premium SaaS
-   Minimal
-   Modern
-   Enterprise-ready
-   Friendly but professional
-   Light theme
-   Large whitespace
-   Strong typography
-   Soft atmospheric gradients
-   Subtle shadows
-   Rounded cards
-   Clean dashboard UI

### Avoid

-   Dark mode
-   Heavy shadows
-   Excessive glassmorphism
-   Excessive gradients
-   Overly colorful backgrounds
-   Excessive decorative elements
-   Generic stock-SaaS appearance
-   Dense layouts
-   Large unnecessary illustrations

The design should feel sophisticated without becoming visually
complicated.

# 34. Responsive Behavior

## Desktop

-   Two-column hero
-   Dashboard on right
-   Full navigation
-   Three-column feature grid
-   Horizontal CTAs
-   Large whitespace

## Tablet

-   Reduce headline size
-   Maintain two-column hero where practical
-   Reduce dashboard scale
-   Maintain card grid where space allows

## Mobile

Stack:

``` text
Header
Hero badge
Hero heading
Hero description
CTAs
Trust indicators
Dashboard
Trusted logos
Feature section
Feature cards
CTA banner
How it works
```

Mobile navigation should become a hamburger menu.

Feature cards become one column.

CTA banner becomes vertically stacked.

Decorative arrows and handwritten annotations can be reduced or hidden
if they interfere with readability.

------------------------------------------------------------------------

# 35. Interaction Design

Animations should be subtle.

Allowed:

-   Button hover transitions
-   Card hover elevation
-   Dashboard floating effect
-   Background gradient movement
-   Smooth scrolling
-   Fade/slide-in section reveals

Avoid:

-   Aggressive animations
-   Fast motion
-   Particle systems
-   Excessive 3D
-   Distracting parallax

------------------------------------------------------------------------

# 36. Accessibility

Maintain:

-   Strong text contrast
-   Visible keyboard focus
-   Semantic headings
-   Accessible buttons
-   Accessible navigation
-   Alt text for meaningful images
-   Proper form/button labels
-   Reduced-motion support

Do not sacrifice accessibility for visual effects.

------------------------------------------------------------------------

# 37. Implementation Principles

The implementation should preserve the visual hierarchy of the
reference.

Priority order:

1.  Hero composition
2.  Typography
3.  Dashboard mockup
4.  Background atmosphere
5.  CTA placement
6.  Feature grid
7.  Spacing
8.  Supporting sections
9.  Responsive behavior

The page should feel like one cohesive product rather than a collection
of unrelated components.

------------------------------------------------------------------------

# 38. Reference Fidelity

The supplied image should be treated as the visual blueprint.

Do not:

-   Change the overall theme
-   Switch to dark mode
-   Rearrange sections
-   Replace the dashboard with a generic illustration
-   Remove the feature cards
-   Remove the trusted-company section
-   Remove the people-focused CTA
-   Use a different color direction
-   Compress the whitespace
-   Add unrelated sections
-   Introduce unnecessary UI elements

The implementation can improve technical responsiveness and
accessibility, but the visual identity and composition should remain
faithful to the reference.
